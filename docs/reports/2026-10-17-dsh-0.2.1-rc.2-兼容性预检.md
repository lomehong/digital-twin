# DSH 运行时 v0.2.1-rc.2 兼容性预检报告

> 日期：2026-10-17
> 结论：**低风险升级，套件无需代码适配**。方法与基线沿用 0.2.0-rc.1 预检
> （`docs/reports/2026-09-27-dsh-0.2.0-rc.1-兼容性预检.md`），并新增两项强化：
> ① 主产物剥离版本号后哈希级对比；② peer 硬门禁全量核查（0.2.x 起 peer 不满足即拒载）。

## 一、依赖集对比（@deepseek-ai/dsh 元包，86 包）

- 全部整体步进 0.2.1-alpha.5 → 0.2.1-rc.2，**零包移除**
- cordis 要求 `~4.0.5`（当前 4.0.4 → minor bump；套件 peer `^4.0.1-rc.4` 满足）
- schemastery `~3.18.5`（dsh-redact 运行时值导入不受影响）
- `@deepseek-ai/dsh-client-runtime` 无 0.2.x 版本 → ClientContext 契约继续稳定

## 二、契约面哈希级对比（13 包，主产物剥版本行后 SHA1）

**11/13 完全一致**：client-ui-conversation、client-ui-layout、llm（llm/stream）、
api-gateway（wire）、settings（configForms/replace）、api-session-controller（会话事件表）、
agent-preset（预设 schema）、agent-preset-registry（auditRows/broken 语义）、credentials、
typert-registry、tool-subagent（含 preset-selection 新契约——上一轮 toolFilter 移除的
适配在 rc.2 下继续有效）。

有差异的 2 处均已钻取核验：

| 包 | 差异 | 对套件的影响 |
|---|---|---|
| client-ui-slots | 镜像中本无副本（client 包走 ModuleLoader）；rc.2 包内核对 `main`/`sidebar.panellist` 存在 | 无 |
| host-webserver | 服务器生命周期重构（listen/close/keepAlive 参数、最长前缀路由、index taps 收敛） | 无——`web.register({kind:'exact'})` 契约面原样，套件 HTTP 路由不受影响 |

## 三、peer 硬门禁核查（0.2.x 起 peer 不满足 = 拒载）

- 套件 11 包 peer 全部为 `>=` 宽范围或可满足形态（v0.2.0 批次已修）：
  - `@deepseek-ai/cordis ^4.0.1-rc.4` → 4.0.5 ✅
  - `@deepseek-ai/schemastery ^3.18.4` → 3.18.5 ✅
  - 其余 `>=0.1.x`/`>=0.1.7-alpha.1` → 0.2.1-rc.2 ✅
- 预设组合行引用的 26 个宿主包在 rc.2 依赖集中**零缺失** ✅

## 四、check-compat 基线

`0 error, 3 warning`（已知良性，与 0.2.0-rc.1 预检一致）。

## 五、升级时的一次性动作（无源码变更）

1. 桌面端升级到 v0.2.1-rc.2 后，重跑 `install-all.bat`（Release 模式）——
   安装器按升级后的宿主镜像自动重写 profile overrides（hostHarnessVersions 自适应）
   并重物化 profile；当前 overrides 若仍锚在旧版会再次出现双版本偏斜
2. 首启冒烟：check-compat 全绿 + Agent 预设页（数字分身/架构师正常加载）+
   套件状态坞/心智/IM 抽查
