# DSH 运行时 v0.2.0-rc.1 兼容性预检报告

> 日期：2026-09-27
> 结论：**低风险升级，套件无需代码适配**。升级时仅需重跑安装器收口 profile 版本锚定。
> 方法：拉取 0.2.0-rc.1 的 12 个契约包与本地 0.1.7-rc.2 逐一做树级 diff；扫描套件构建产物的运行时值导入；check-compat 审计基线。

## 一、依赖集对比（@deepseek-ai/dsh 元包）

- 0.2.0-rc.1 依赖 **82 包，全部整体步进 0.1.7-rc.2 → 0.2.0-rc.1**，**零包移除**——
  2026-09-16 事故类（组合行引用已移除包 → 整份组合拒绝挂载）不可能发生
- `@deepseek-ai/cordis` 仍 `~4.0.4`（套件 peer `^4.0.1-rc.4` 满足）
- `@deepseek-ai/schemastery` 仍 `~3.18.4`（dsh-redact 的运行时值导入不受影响）
- `@deepseek-ai/dsh-client-runtime` **没有 0.2.0 版本**（npm 最新 0.1.1-rc.2）→
  ClientContext 契约未变，客户端 `apply/inject/slots` 形态安全

## 三、套件运行时值导入（仅 2 处，逐一核验）

| 导入 | 消费方 | 核验结果 |
|---|---|---|
| `@deepseek-ai/dsh-tools`（defineTool） | dsh-memory | 0.2.0-rc.1 导出清单逐字节一致 ✅ |

其余套件包的宿主引用均为**类型级导入**（构建期擦除）或**ctx 服务面**（由宿主进程提供，随运行时走）。

## 四、静态声明面

- 各包 peerDependencies 均为**宽范围声明**（`>=0.1.7-alpha.1` / `>=0.1.2-rc.1` / `^4.0.1-rc.4`）——
  0.2.0-rc.1 天然满足，**无需收口**
- profile 的 overrides 锚定由安装器 `hostHarnessVersions()` 从宿主镜像**自适应读取**——
  运行时升级后镜像被重写，重跑安装器即自动收口到 0.2.0-rc.1，**无需改源**

## 五、check-compat 基线

`0 error, 3 warning`（均为已知良性：dsh-computer 未部署的存量提示、预设编程注册不落盘的跳过提示）。

## 六、升级时的一次性动作（无源码变更）

1. 桌面端升级到 0.2.0-rc.1 后，重跑 `install-all.bat`（Release 模式）——
   安装器自动按新镜像重写 overrides 并重物化 profile
2. 首启冒烟：check-compat 全绿 + 心智/状态坞/脱敏抽查（本报告的核对点可复用）

  的外发不经脱敏（im-channel 出站已接线）。是否接线留主人拍板。
