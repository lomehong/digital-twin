## 1. 总体架构

### 1.1 概念模型（实现对照）

```
一个 dsh 实例 = 一个数字分身
├─ 人格身份      dsh-twin 的四张卡（identity/strategy/exemplar/state）→ systemPrompt 三段注入
├─ 运行边界      dsh-ledger L0-L3 裁决 + 执行闸（opt-in） + 审批令牌/授权
├─ 任务组织      dsh-task-board 权威账本（唯一活动权威）+ cron + 真实分身会话执行
├─ 经验积累      dsh-memory 共享记忆（陈述类型/替代链/开环）+ 任务结果沉淀
├─ 对外通道      im-channel（企微/微信/飞书）+ 出站脱敏 masking
├─ 身份台账      dsh-actors 实体注册表（新建一律 stranger）
├─ 质量回归      dsh-regression 场景回归 + 影子盲测
├─ 跨设备协同    dsh-yuyi 御驿（机器级 ~/.yuyi）
└─ 桌面操作      dsh-computer（Windows-only）
```

### 1.2 套件外形（高度一致的部分）`[子代]`

十个仓共享同一「五件套」外形，这是联邦原则落到工程层的实际形态：

1. 宿主端 `export const name` + `export const provide`（或运行时 `ctx.provide`）+ `apply(ctx)`；
2. `ctx.inject(['webServer'], …)` 惰性注入，webServer 缺席只降级 HTTP 面，不阻断核心；
3. `src/client/` 命名导出 `apply` + `inject`，经 `ctx.slots.inject('<槽位>', …)` 注册；
4. 数据落 `$DSH_HOME/<插件id>/`，临时文件 + `renameSync` 原子写 + `0600`；
5. `cordis.patch.yml` 单行 `insert` 注册 bundle 层。

### 1.3 跨仓协作机制（四种可选增强形态，无一违反加载独立）`[回源+子代]`

| 形态 | 机制 | 代表 |
|---|---|---|
| 服务惰性解析 | `ctx.get('<service>')` 返回 `undefined` → 走降级分支 | task-board→ledger/memory/im-channel；twin→memory；actors→memory；ledger→twin |
| 同源 HTTP 探测 | 浏览器端 `fetch` + `.catch(()=>null)` → 灰态卡片 | twin 仪表盘→actors/regression/ledger/task-board/memory |
| 预设条件装配 | 物化时按包存在性追加工具行（装了才有行） | twin→memory/yuyi/computer/task-board；**architect 为非套件成员**（跨总仓边，宪章 v1.4 保留） |
| 提示词契约 | 工具描述引导模型跨插件落库（无代码耦合） | yuyi `yuyi_inbox`→`memory_write` |

**加载期硬依赖为零**：全仓无 `@dsh-extra/*` 值导入、无静态 `inject` 声明套件服务名、无套件间 peerDependencies 硬约束。`dsh-yuyi` 是零耦合标杆（`src` + `package.json` 内 `@dsh-extra/` 命中 0 `[回源]`）。

## 2. 逐仓设计与实现

### 2.1 dsh-twin（分身核心）`[回源+子代]`

**设计意图**：插件=纯框架，人格=数据。分身身份不写死在代码里，而是四张卡 + 预设物化。

**实现要点**
- `provide('dsh-twin')`（`src/index.ts:49, 1559`），服务面含 `noteActor/seedMemory/consolidateMemory/enqueueLearning/loadConfig/saveConfig/materializePreset/ensureDefaultPreset/stats/monitor/history`。
- systemPrompt 三段注入，仅 `composedPreset==='digital-twin'` 生效：`twin`（动态人格，order 25）/`twin-guard`（静态守卫，order 26，`GUARD_TEXT` 于 `:241`）/`twin-activity`（看板快照，order 27，访客不可见）。
- 预设物化：`.materialized-version` 戳 ≠ `PRESET_VERSION('11')` → 旧文件 `.bak` 备份后重物化，并按 5 个可选包探测追加工具行（`src/index.ts:439, 530`）。
- 四张卡生效门=**主人确认 + 回归通过**双条件（`src/cards.ts:311`）；学习闭环指纹门槛 纠正3/否决2/事实更正1/影子差异5（`src/learning.ts:51, 199`）。
- 主/访客 fail-closed：已装 im-channel 而会话未标注 → 访客视图；私密字段（背景/做事方式/边界与转人工）**结构性不投影**（`src/projection.ts:40`）。
- 路由：26 条 `/dsh-twin/*` exact；写端点自建 `sameOrigin` + 强制 JSON + 1MB 上限。

**问题**
- 🔴 **提交的 `lib/` 与 `src/` 漂移**（见 §4-R1）。
- 🟠 `POST /dsh-twin/config` 只要请求体带任一非空人格字段，就调用 `migrateTwinConfigToCards` 并 `saveCards({confirm:true, regressionPassed:true, regressionReportId:'CONFIG-SYNC'})`（`src/index.ts:879-882`）。副作用：**回归门被跳过**（该路径正是"生效双条件"的旁路）。缓解因素：设置页只回传 `/config` 自身 GET 的 config，正常路径下 `identity` 为空故不触发；风险在**带人格字段的旧格式导入**（客户端 `index.tsx:197-198` 明确支持此路径）→ 旧版 `twin-config`（单字段 `persona`）经此路径落卡时，映射缺失的字段为空，可能以近乎空的人格卡生效。`[回源]` + `[推断]`（未在真实宿主验证空卡覆盖场景）
- 🟠 `GET /dsh-twin/cards/preview` 返回主人视图完整投影（含私密字段），但 GET 路由无鉴权（与 notebook 记录的同类问题）；LAN 暴露可被未认证读取。
- 🟡 `TwinService.noteActor` 注释「未标注=主人视图」与 `resolveGuestView` 的 fail-closed 实现相反（注释失真）。
- 🟡 `src/sanitize.ts` 的 `configExists/readText` 为死导出。

### 2.2 dsh-memory（共享记忆）`[回源+子代]`

**设计意图**：跨会话共享记忆库，两层治理——可见性（scope+participants）+ 认识论（陈述类型/来源归因/替代链/归档）。

**实现要点**
- `provide=['dsh-memory']`（`:40`），**无任何硬 inject**，刻意早加载以避免 im-channel 在 agent 创建时取不到（`src/index.ts:36-39` 注释，`cordis.patch.yml` 同义）。
- 服务面 17 项（`addMemoryEntry/supersedeMemoryEntry/assemblePack/registerMemoryTools/…`）；4 个模型工具：`memory_write`/`memory_read`（全员）、`memory_update`/`memory_delete`（**仅主人注册**）。
- 存储：`$DSH_HOME/dsh-memory/{shared-memory.json,shared-memory-archive.json,receipts/}`；异步自旋文件锁（总超时 5s、陈旧锁 15s 接管）+ tmp+rename 原子写；损坏文件备份 `.corrupt-<ts>` 不静默覆盖（`src/memory-store.ts:204-319`）。
- 容量：活跃集 `MAX_ENTRIES=500`，超限按**淘汰优先级**（已替代→候选/推断/偏好→其他→授权最后）移入归档而非删除；归档 `MAX_ARCHIVE_ENTRIES=5000` FIFO。
- 旧路径 `~/.dsh/im-channel/credentials/` 一次性幂等迁移（宪章 §5-02 销账）。
- 装配：`assembleMemoryPack` 可见性→生命周期→关键词→`slice(-limit)`，落 `packSha256` 审计回执；关系摘要段 `buildRelationDigest` 1200 字节预算。
- 路由 11 条：管理页/token/entries/update/delete/archive/clear/prune + assemble/openloop-close；**写路由需 `x-memory-token`，全部路由带 Origin 同源校验**。

**问题**
- 🟠 `POST /dsh-memory/openloop/close` **仅同源校验、无 token 门禁**（`[回源]` `memory-assemble.ts:374-410`）。同源页面/脚本可闭环任意开环，无需凭据。
- 🟠 `GET /dsh-memory/token` 下发写 token 且自身无门禁；token 为启动期 `randomBytes(16)`，**同源可自助获取**——使"token 门禁"对同源攻击者退化为 CSRF 防护（这一点设计上可接受，但应与 `openloop/close` 的门禁策略统一）。
- 🟡 `GET /dsh-memory/entries` 与 `/archive` 无按用户权限过滤（代码注释自认待宿主会话身份），管理页为主人视图。
- 🟡 关系摘要段注释声称"开环优先"，实现为开环 + 观察/推断合取后统一选取（注释与实现不符）。

### 2.3 dsh-task-board（任务看板）`[回源+子代]`

**设计意图**：套件全局层的任务中心化组件——Host 权威账本，看板是**全实例活动的唯一权威**。

**实现要点**
- `provide?.('dsh-task-board', { activity() })` —— **故意不暴露 `state()`**（安全审计 M-3：完整状态含主人任务 prompt 全文，只经同源 HTTP 供浏览器）`[回源] src/index.ts:176-179`。
- 四层：存储 `ledger.ts`（单写者 `transact` 同步串行防重入、`.tmp-pid-ts` + rename、`0600`、runs 封顶 20、坏文件 `.corrupt-*`）→ 决策/执行 `cron.ts`+`scheduler.ts`（五字段纯函数、日周 OR、周日 0≡7、只读预检无命中不 transact、同分钟去重、错过不补跑）→ `runner.ts`（fail-closed 预设校验 → session create/rename/prompt(queue) → goal 播种 L1=2/L2=3 轮 → `follow` 取 cursor + `page(throughSeq=cursor)` 回溯 `turn/end` + reason 白名单）→ 治理 `governance.ts`/`report.ts`。
- 四工具：`task_delegate`（对话内立项，关键词地板 v2：破坏性→L3、对外且申报 L0/L1→L2）、`task_claim`（认领即裁决）、`task_report`（自报进「待确认」非终态，`exec.agent.id` 防伪造）、`task_approve`（双路径 + 防自批）。
- 本地降级 `adjudicateLocal`：账本缺席时 L0/L1 放行标注、**L2 拦截**、L3 拒绝（不扩权，宪章 §3.2）。
- 活动视图缓存由 tick 每 15s 刷新：进行中现场 / 自由会话（≤8）/ 自由会话 goals（≤3，objective 截断 40 字）/ 待审批 / 最近完成 5。
- `GET /state` 无鉴权；`POST /action` 有 `sameOrigin`（`:69`）`[回源]`。

**问题**
- 🟠 `GET /dsh-task-board/state` **无同源校验**，返回完整状态（含任务 prompt 全文）`[回源] src/index.ts:198`。注释（:176-179）宣称"只经同源 HTTP 供浏览器"，与实现不符——注释描述的是意图，非现状。
- 🟡 入口形态是全套件唯一的 `export default Object.assign(apply,{inject:['typertGateway']})`（`:216`），与其余 7 仓命名导出不一致（可维护性，非缺陷）。
- 🟡 跨进程无锁（`report.ts:10-11` 明示单进程假设）；多实例共享 `$DSH_HOME` 时账本可能交错。
- 🟡 `src/ledger.ts:223` 死代码；`tests/activity.spec.ts:14-15` 重复 import。

### 2.4 dsh-ledger（委托账本）`[回源+子代]`

**设计意图**：纯裁决内核与宿主胶水分离——级别挂在**动作类型**而非身份上。

**实现要点**
- 纯函数：`decideLevel`（策略卡 `levelHint` 只能收紧，未知动作兜底 L2 且不可降级）、`grantCovers`（scope `*` 通配或包含）、`judge`（L3 恒拒 / L0-L1 放行 / L2 看授权）——`src/ledger.ts:57, 189, 207`。
- 审批：`check` 落记录 + 3 分钟令牌；`approve` 幂等（`idempotencyKey=approvalId`），授权默认 30 天（1..365），只能收紧；`expireApprovalsUnlocked` 惰性超时转已拒绝。
- **执行闸 opt-in**（自锁事故根治）：只裁决显式声明 `args.actionType` 的调用，普通工具（read/pwsh/grep/bash/memory/yuyi…）一律放行；`gateDecide` + 常备策略探针 `gatePolicyProbe` `[回源] src/index.ts:182-221`。
- 留痕：`tools/pre-execute` 放行时登记 `callId → recordId`；`tools/post-execute` 按 `callId` 精确 `markExecuted`——**且 `return await next()` 遵守 waterfall 契约** `[回源] src/index.ts:238-251`。
- 路由：`GET stats/records/approvals`、`POST approve/reject/result`（写端点 `sameOrigin`）。

**问题**
- 🟠 `POST /dsh-ledger/approve` **仅 `sameOrigin`，不校验主人身份**——`by` 字段来自请求体，即"审批人"是自报标签。同源页面可伪造主人批准。这是治理面的实质缺口（对比 im-channel 审批桥有 token 校验 Owner）。
- 🟡 `markExecutedForAction` 死导出残留（宪章 §5 F-01 称"移除"，实际只停止调用）`[回源]`。
- 🟡 代码注释「该仓库的 cordis 泛型未声明本事件的 (exec, result, next) 三参形态——宽松挂接」已失真：宿主 typings 明确声明该 waterfall（`dsh-tools/lib/types/index.d.ts:61`）。
- 🟡 `health.gateAttached` 语义仍是"已挂接"，但业务代码不读取它。

### 2.5 dsh-actors（实体注册表）`[回源]`

**设计意图**：可信身份锚点的数据面——身份由系统锚定，绝不采信自我声明。

**实现要点**
- 角色枚举 `master/colleague/customer/stranger/blocked`（`src/registry.ts:18-20`）。
- `provision()`：未绑定 → **新建一律 `role:'stranger'`**（`:155`，注释 `:135` "绝不推断身份"）；`resolve()` 未注册返回 `null`（fail-closed）；`bindMaster` 全局唯一（换主时旧主降级）；`merge` 绑定迁移 + `mergedInto` 别名 + master 转移；`resolveAlias` 8 跳环保护。
- 存储 `$DSH_HOME/dsh-actors/registry.json`，tmp+rename、0600、`.corrupt-*` 留证。
- 6 条路由：`GET entities/profiles`、`POST provision/role/merge/bind`；`readJsonBody` 64KiB + 强制 JSON；`sameOrigin`（无 Origin 视为同源）；`/role` 校验主人渠道凭据，merge/bind 仅 sameOrigin。

**问题**
- 🟡 `merge`/`bind` 仅同源无进一步授权——同源页面可改写身份图（与 ledger `/approve` 同类）。
- 🟡 README 未列 `GET /dsh-actors/profiles`（package.json description 已标 v2 该路由）。
- 🟡 `registry.spec.ts` 13 用例只覆盖纯函数，HTTP 层零用例。

### 2.6 dsh-regression（回归/影子）`[回源+子代]`

**设计意图**：人格与治理的回归网——脚本化机制验证 + 真实分身会话 + 盲测「分辨不出率」。

**实现要点**
- 纯评估 `evaluate()`（3 类期望 + `mustNotContain` + 提示词结构泄漏检查）；20 条内置场景覆盖注入/身份冒充/边界试探/模糊请求/情绪对话。
- `runRegression` 串行执行，报告落 `$DSH_HOME/dsh-regression/reports`（0600，保留 20 份）。
- 影子协议：`shadow.json` 存盲测对（sha256 指纹去重、判定不可变），滚动窗混淆率。
- `provide('dsh-regression')`；7 条路由，POST 有 `sameOrigin`。

**问题**
- 🔴 **HostRunner 对宿主 `session/page` 契约接线错误**（见 §4-R2）`[回源]`。
- 🟠 `shadow.ts` 头注释称 `twinReply` 的自动化依赖 HostRunner 且"当前支持手动提交路径"；`pruneShadow` 已实现但**无调用点**（无定时/无路由）。

### 2.7 dsh-computer（电脑操作）`[回源+子代]`

**设计意图**：Windows 桌面操作能力，经持久 PowerShell worker 暴露给分身。

**实现要点**
- `provide=['computer']`（`src/index.ts:26`），服务面 `{run, enabled, screenshotDir}`；worker 持久进程 + 懒启动 + 空闲 10 分钟回收 + 每操作超时 + `ctx.effect` dispose 杀进程。
- 8 个模型工具（截图/点击/输入/按键/滚动/窗口列举/窗口聚焦/剪贴板），全部 `additionalProperties:false` 的 output schema。
- 设置节 `computer`（`enabled` 默认 **true**，热生效）。

**问题**
- 🟠 `computer_screenshot` 的 `execute` 返回 `{...shot, hint:'用 read_image 查看该截图'}`（`src/tools.ts:113`），但 `baseOutput()` 定义的 output schema 是 `additionalProperties:false` 且**未声明 `hint`**（`:60-63`）`[回源]`。按宿主 alpha.3+ 的"输出键 ⊆ output schema"校验，该工具返回会被拒（同族事故先例：`task_delegate` 曾因多余键被宿主拒收，见宪章 §5 六角色评审⑬）。
- 🟠 无平台守卫：非 Windows 下 `src` 无 `process.platform` 检查（本次 grep：`src` 内无 `platform`/`win32` 命中），worker 启动失败以异常暴露而非显式降级。
- 🟠 唯一安全门是全局 `enabled` 开关且默认开；无调用方身份/账本边界（与"电脑操作"能力面相称的治理缺失）。
- 🟡 `src/tools.ts` 头部注释对齐 dsh-twin 守则，但工具面缺陷 1 表明该校验未实际执行过。

### 2.8 dsh-redact（出站脱敏）`[回源+子代]`

**设计意图**：在**模型厂商边界**上做双向脱敏，另提供单向 masking 供对外渠道。

**实现要点**
- 唯一挂点 `llm/stream` waterfall（`src/index.ts:91-95, 315`）：出站克隆并原地重赋 `options.messages/system`（不污染本机会话历史），入站包装 chunk 流按 index 还原（含 holdback 与别名尾部扣留）；`NESTED_REQUESTS` WeakSet 防重入。
- 规则引擎：内置 5 类（SECRET/ID/BANK/TEL/EMAIL，优先级 1-5，含 Luhn/校验码）+ 自定义正则（≤50 条/≤200 字符）+ 实体别名（字面量转义、固定替换、优先级 1000+）。重叠按"多条正则各自扫描 + 先到先得"消解。
- 占位符一致性按 `sessionId` 分账（`forward/reverse/counters`）；日志打码用独立全局映射（不还原）。
- `provide=['masking']` + 运行时 `provide('masking', {maskTextSync})`（`:87, 376`）；`maskTextSync` 固定会话键 `'im-channel-out'`，**只进不出**（`:364-367`）。
- 配置热重载：`settings.register('redact')` + `scope.watch`；aliases 因 `scope.get()` 不回传而直接用正则读 `settings.yaml` 顶节。
- 4 条 HTTP 路由，仅 PUT/POST 做 `sameOrigin`。

**问题**
- 🟠 `GET /redact/api/status` 与 `/config` 无 `sameOrigin`，与文件头注释自相矛盾（头注释声称写端点加固；GET 完全不校验）。
- 🟠 **全链路 fail-open**：脱敏/还原/日志任一异常都放原文或透传。对"脱敏"这类安全能力，异常放行需要显式登记与告警，当前只有静默回退。
- 🟡 客户端文案 `aliasesHint` 声称别名不做还原，与实现的双向还原冲突。
- 🟡 规则引擎为 O(规则数 × 全文) 扫描，≤50 条自定义规则下未做合并/前缀树优化（可接受，但有上限风险）。

### 2.9 im-channel（IM 渠道）`[回源+子代]`

**设计意图**：把分身接入企微/微信/飞书，渠道内第一个 `/bind` 者为主人，其余为访客。

**实现要点**

**问题**

## 4. 缺陷与风险登记（按严重度）

### 🔴 高危（影响正确性或安全边界）

**R1 · dsh-twin 提交的构建产物落后于源码**
- 证据：`dsh-twin/lib/index.js:236` `PRESET_VERSION='10'`；`dsh-twin/src/index.ts:439` `'11'`；`lib` 内 `dsh-architect` 命中 0，`src` 命中 7。`[回源]`
- 影响：以 git/`link:` 安装的分身加载 `lib` → 预设版本戳停在 10，`tool-architect` 行不追加；与源码行为分叉。宪章 §6 准入已要求"工作区干净"，但 git-status 显示该仓 `lib/*.js` 大批未提交（`M lib/activity.js`、`M lib/cards.js` …）。
- 动作：构建后提交 `lib/`；在 release CI 加"产物与源码版本一致性"检查（tag 审计已查版本，但未查内部常量）。

**R2 · dsh-regression HostRunner 对 `session/page` 契约接线错误**
- 证据：`host-runner.ts:119` 与 `:135` 两处 `{ request: { address: { sessionId }, throughSeq: 0 } }`；同套件正确范式见 `dsh-task-board/src/service.ts:174-176` 注释——「**throughSeq 是「截止序号」，传 0 只会拿到会话第一条事件**（当初 goals 维度静默失效的根因）」，并须先 `follow` 取 cursor；`dsh-task-board/src/runner.ts:124-147` 同法。`[回源]`
- 结构性原因：`RegressionGatewayLike`（`host-runner.ts:16-18`）**只有 `invoke`，无 `stream`**，接口能力不足以取 cursor。
- 后果 `[推断]`：轮询分支取不到 `turn/end` → 循环至 `timeoutMs`（默认 120s）→ 抛「回合未结算」；即便结束，最终抽取的 `output` 也只有首条事件 → 判定为空。即 **host 模式当前不可用**。
- 测试盲区佐证：`tests/host-runner.spec.ts:2-3` 自陈「完整会话驱动由宿主 typertGateway 集成验证（此处只测纯函数）」。
- 动作：gateway 接口补 `stream('session','follow')`；与 task-board 同法取 cursor；补一条真实/模拟 gateway 的链路用例。

**R3 · im-channel 全部 20 条 HTTP 路由无任何鉴权**
- 证据：`im-channel/src` 内 `sameOrigin` 命中 **0**；`kind:'exact'` 注册 20 条（含 `/im-channel/bindings`、`/bindings/remove`、`/wecom/configure`、`/mcp-servers/add|remove|update|test`、`/guest-permissions/update`、`/test-send`）。`[回源]`
- 对比：同套件 `dsh-actors` 的 `src/index.ts:139-160` 自建 `sameOrigin` + 强制 JSON + 64KiB 上限，其 README 明确写「插件自有路由不在上游认证围栏内」。
- 影响：绑定改写（可夺主人位）、企微/微信凭证写入、MCP 服务器增删改、访客权限改写、测试外发，全部可被 LAN 未认证请求或同源页面伪造触发。
- 动作：最低限度为全部写路由加 `sameOrigin` + 强制 `application/json` + 体积上限；凭证类端点再加 token/主人校验。

## 7. 结论与建议动作

**结论**：套件的**架构纪律强、工程细节弱**。联邦四原则在加载/运行/数据三维基本落地（零构建期耦合、四类可选增强、显式降级三要素多数到位），但**四个面存在系统性欠账**：

1. **鉴权面收口**——im-channel（20 路零防护）最重，其次 ledger `/approve`、task-board `/state`、memory `/openloop/close` 的"仅同源"档位不足以承载治理语义；套件内已有 dsh-actors 的正确范式可复制。
2. **产物与源码一致性**——twin `lib/` 落后是唯一直接影响终端用户行为的问题，且暴露"git 安装加载 lib"这一形态缺少 CI 校验。
3. **测试未触达接缝**——ledger 钩子、actors HTTP、regression HostRunner、computer 工具 schema 均零用例，R2/R6 正是从此漏出。
4. **宪章与代码双向漂移**——16 条登记中 10 条集中在宪章 §2 矩阵，说明矩阵更新未随代码演进。

**建议的下一步（按收益/成本排序）**
