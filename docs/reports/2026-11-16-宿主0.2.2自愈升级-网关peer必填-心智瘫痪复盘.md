# 宿主 0.2.2-rc.3 自愈升级 × 网关 peer 必填——心智瘫痪事故复盘

> 日期：2026-11-16
> 结论：**三层叠加故障**——宿主契约变更（诱因）× 套件 6 周未发布（放大器）×
> 宿主自动升级绕过人工升级闭环（流程洞）。已修复并部署 mind v0.10.43 /
> task-board v0.2.9 / regression v0.2.3。

## 一、现象

- 心智主页空转，时间线被错误刷屏：2026-11-16 全天 **2179+ 条**
  `唤醒失败：Cannot read properties of undefined (reading 'signal')`，
  自发/反应性每 ~8 秒一拍，seq 从 53 刷到 2591+。
- `run/state.json` 的 `spend.date` 停在 2026-10-01（账本只在成功唤醒时滚动）；
  10 月 1 日的待办（openPendings seq 49）至今未清——**从 10 月 1 日起无一次成功唤醒**。
- 时间线 10-01 → 11-16 之间零写入：期间 profile 插件目录实际处于缺装/坏装状态，
  心智根本没在跑；11-16 00:51/00:58 两次宿主重启后插件被补装回来。

## 二、根因链

1. **诱因（契约层）**：11-16 08:57 桌面壳自愈升级核心 0.2.0-rc.2 → 0.2.2-rc.3。
   新网关把 `InvokeRemoteRequest.peer`（PeerScope）升为**必填**
   （types.d.ts: "every carrier and in-process caller names it explicitly"）；
   进程内调用者不带 peer 时 `assertPeerLive` 读 `peer.signal` → 即时间线里的报错。
   08:58:36 第一条错误，与新核心重启时刻吻合。
2. **放大器（版本层）**：套件 Release 通道冻结在 10-01（GitHub latest = dsh-mind
   v0.10.4 / task-board v0.2.0 / regression v0.2.2），工作区里 6 周 38+ 补丁
   （mind v0.10.42、board v0.2.8）从未发版重装。自愈升级把冻结旧包原样装回，
   旧代码撞新契约，一拍都跑不过。
3. **流程洞（治理层）**：`UPGRADE-CHECKLIST.md` 的标准闭环是「核心升级 →
   check-compat → 适配 → build/test → install-all」。宿主**自动**升级绕过了闭环；
   且套件兼容性预检的方法只做 wire 面产物哈希对比（wire 路径由载体补 peer，
   哈希一致），**漏检服务级 invoke 契约**——peer 必填正是从服务级面进来的。

## 四、防复发（待办）

1. **发版**：三仓库推送 GitHub Release（v0.10.43 / v0.2.9 / v0.2.3），让
   `.suite-tarballs`/自愈通道拿到新包——否则下次自愈升级又装回冻结旧版。
2. **预检方法升级**：check-compat 增加「服务级 invoke 契约」检查项——对套件
   消费的宿主 Remote 面（typertGateway/session/goals…）做形参结构断言，
   覆盖 peer 这类服务级必填项；wire 哈希对比继续保留但不再作为唯一依据。
3. **宿主自动升级挂钩**：桌面壳自愈升级完成后，自动触发套件
   check-compat + 提醒重装（或至少给主人推送「套件需重验」通知）。
4. **时间线洪峰治理**：同类每拍错误应聚合（同一 message 连续 N 拍只落一条
   计数行），既保可观测又防刷屏——本次 2179 条同文错误即该缺陷的实证。
