# 数字分身丰富提案 v2——以心智插件为中心，参考 DeepSeek-Office

> 日期：2026-10-29（v2，重写 v1）
> v1 的错误：把重心放在「可视化与团队身份」，心智插件只是数据源。
> v2 重新思考的基线：**心智插件（dsh-mind）是分身的本体——时间线/唤醒节律/函数菜单/
> narrate 叙事层/请求账/成本纪律已经是完整的「心智生活」生产系统；
> DeepSeek-Office 做的事是把「agent 的工作与生活」翻译成可感知的空间与行为语言。
> 套件缺的不是素材生产，是「翻译层」与「承载层」。**

## 一、对齐认知：Office 与心智插件的理念同构

| DeepSeek-Office 的纪律 | 心智插件的对应（已有） |
|---|---|
| 不建聊天系统，复用 Harness Sessions + 原生 composer | 不建生活数据，复用时间线 + narrate 层 |
| Bot 的状态变化 → 办公室行为（走进来/坐下/举手） | 唤醒的函数选择/narrate 步骤 → Being 的状态（已有三态） |
| 本地时间 → 阳光/晚灯 | 静音时段/退避档位 → Being 睡姿/呼吸节律（已有雏形） |
| 任务间的小休息（咖啡/阅读/街机） | 空醒短路的机械拍、learn 的阅读、deep think 的专注（已有语义，缺可视化） |

**结论：双方在「复用既有真相源、只建视觉世界」上是同一纪律。**
心智宿主半（调度/审计/成本）在 DS Bot 里没有需要学的——mind 的节律与成本纪律更严；
丰富点集中在 **client 半的存在层与生活层**，且全部素材已在时间线里。

## 二、提案（以心智为中心重排）

### ① Being 剧场化（P0，dsh-mind client，1-2 天，零新数据）

Being 从「三态呼吸球」升级为「行为剧场」——**渲染素材就是心智已有的输出**：

- `fetchStatus` 的 tail 已经是 narrate 化的生活步骤（「我在安静一会儿」「空醒短路」「正在运行 ×××」）
  ——把最新一步的类型映射为 Being 的可见微行为与一行字幕：
  - think → 专注姿态（光圈收缩）；learn → 翻书微动；act → 敲键节奏
  - idle → 歇息（已有「我歇了一会儿」叙事）；静音时段 → 睡姿（已有 asleep 色温）
- 交互层（参考 Office 的 poke/衣柜情绪设计）：摸头 →「别闹，在想事」、连点 → 头晕、
  静音时段轻拍 →「嘘」——反馈只改字幕与动画，**不新增心智状态**（避免为表情引入状态机）
- 请求/消息角标已有（P5），保留

### ② 「TA 的一天」上浮到存在体面板（P0.5，同包）

Being 点击展开的面板，从「跳转心智页的入口」升级为**内嵌的迷你生活流**：

- 今日时间线的 narrate 化展示（复用 MindPage 已有的 timeline 渲染，量裁剪到今日）
- 今日 spend / 请求单 / 下次唤醒倒计时（数据全部已在 /dsh-mind/status 与 timeline）
- 目标：主人不进心智页，右下角就能「看见分身的一天」

### ③ 心智节律 → 环境语言（P1）

- 退避档位/静音时段/deep think 周期 → Being 周围环境的光晕节律与动画频率
  （数据已在 status：backoffLevel/quiet/running）
- 语义示例：深度思考拍 → 光晕收束变亮；长静默（watchdog 邻域）→ 呼吸放缓变暗——
  **把调度器的内心状态外化为氛围**，依然零新状态

### ④ 分身的「手机」与「会议」（P2，按主人实际用法决定）

- **手机层**（Office 的 Phone 语义）：Being 长按/右键弹出随身面板——
  请求单一键答复、任务看板速览、时间线速翻。数据源全是既有服务
- **会议事件化**：若 agent-team 群组成为分身的常态协作，把「会议」作为时间线一等步骤
  （与会者/议题/结论落时间线），可视化为主位入席场景——**先有真实用法再做**

### ⑤ 办公室渲染层（P3，独立立项）

- 数据源明确为**心智时间线 + narrate**（「分身的一天」空间化），
  而非 agent-team——与 v1 的关键区别
- 技术参考 Office：Three.js 正交视角 + 程序化场景 + GLB 角色；
  资产需自有（Being 的视觉延展=自有 IP，避开其 © 资产）

## 三、纪律（从 Office 学到的最重要一条）

**Office 没有建聊天系统**——它复用 Sessions + 原生 composer，只建视觉世界。
心智提案同款纪律：**所有渲染层零状态、零新数据**，真相源始终是时间线 + state.json。
任何需要「新增心智状态才能画」的想法，先问时间线里是不是已经有了。

## 四、明确不做

- DS Bot 团队壳（主人已拍板）
- 为表情引入新的心智状态机（① 的交互只改字幕/动画）
- 跳过心智直接渲染 agent-team 原始会话（v1 的错误方向）
