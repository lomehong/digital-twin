# 任务看板（dsh-task-board）设计决策记录

> 2026-09-04 与主人多轮沟通确认的设计决策。本文档是实施的依据；实施中若需偏离，
> 先与主人确认再修订本文档。背景参考实现：zhu1090093659/dsh-web 的 dsh-task-board
> （仅参考设计思想，代码全部自主实现）。

## 决策一：自主实现，不安装外部包

参考外部任务看板的架构模式（见决策四清单），代码自主编写，按套件统一标准交付
（测试、中文注释、README、LESSONS）。仓库 `dsh-task-board`，成为 digital-twin
套件第 10 个子模块。外部代码零复制，避免供应链与版权耦合。

## 决策二：账本裁决是一等公民（与外部实现的本质差异）

> **宪章 v1.0 修订（2026-09-05，主人已确认实施会话）**：账本缺席时的降级语义为
> **L0/L1 放行并标注「无账本治理」、L2 拦截并尽力通知主任、L3 一律拒绝**——
> 降级态不扩权（宪章 §3.2）；账本在场时语义与本决策完全一致。

外部实现的权限门禁是看板内部的孤立确认；我们的版本里 **dsh-ledger 是任务执行的
唯一授权层**：

```
任务创建（声明动作级别 L0-L3）
  → 执行前过 ledger check 裁决
    → L0/L1 放行 / L2 阻断并产生审批令牌 → 今日待办「待批审批」→ 主人批准发授权
  → 真实分身会话执行
  → 结果回填账本（fillResult）→ 今日待办看到闭环
```

完整「布置 → 授权 → 执行 → 回填」治理闭环。定时自主任务从第一天就在治理框架内。

## 决策三：一次性完整落地，不分 MVP

功能基线（一次做完）：

1. 五列看板 UI（待规划/待办/进行中/已完成/已失败）+ 搜索、详情、归档/恢复
2. 手动执行 + cron 定时调度（5 字段、错过跳过不补跑、本地时区）
3. 账本联动闭环（上条）
4. 真实会话执行：每次执行新建 dsh 会话，钉扎 workspace，fail-closed 校验
5. Host 权威账本：独立持久化 + 原子写，浏览器只是异步视图
6. SSE 实时同步 + 修订快照
7. 执行历史每任务封顶 20 条
8. 重启确定性恢复（有会话 id 的运行中任务恢复观察；无 id 的中断取消不重发）
9. 续接卡：会话 FREEZE 快照生成任务卡（脱敏 [REDACTED]、斜杠命令拒绝、字段限长、
   来源会话戳、来源声明包裹执行防提示注入）
10. 交接包：钉扎三元组 + 文档/脚本引用随任务提示词前置
11. idle-sleep 保护（可选，默认关）
12. 系统提示词公告注入（可选开关）

## 决策四：digital-twin 预设升级为全工具（前置条件）

分身预设不再是 conversation-first：shell、文件系统、pwsh、电脑操作等全部工具
开放给分身。**治理靠账本裁决 + 输出门禁 + 访客隔离，不靠剥夺工具**。分身预设
由此可以安全地成为全局默认预设，消灭「多预设多人格」的割裂。

实施顺序上，本项是任务看板的前置条件——全工具分身才派得出去干活。

## 决策五：任务中心化——一个 dsh 就是一个任务看板

任务是 dsh 的第一等组织单元，会话是任务的执行实例（一个任务可被多个会话推进；
会话归属任务；自由聊天是无任务归属的特例）。dsh 的定位从「聊天工具 + 一堆插件」
升级为「任务驱动的自治工作台」：看板是大脑，分身是手脚，会话是具体执行，账本是
行为边界，记忆是经验积累。

由此 dsh-task-board 的定位是**核心组织层**而非普通插件：需要深度耦合会话系统
（会话创建/列表与任务绑定），可能涉及宿主层会话模型扩展。

## 决策六：身份与权限分离——一个分身人格，三条权限线

预设（人格身份）统一，但工具能力按对话者身份分层，访客线是独立治理轨道：

| 场景 | 分身能力面 | 治理来源 |
|---|---|---|
| 主人日常会话 | 全能力 | 主人是权限源头 |
| 定时任务执行 | 全能力 + 账本裁决 | 不可逆动作过 ledger（L0-L3 + 审批） |
| 访客对话 | **默认收窄**（无工具或最小集） | 增量能力必须 Owner 批准授权；未批准不可用（fail-closed）；可随时撤销；批准动作入账本授权体系与今日待办 |

切忌把「预设统一」误推广为「权限统一」：访客不是「另一个预设的分身」，而是
「同一个分身被 Owner 授权了有限能力后的样子」。现有 im-channel 访客权限白名单
+ noteActor 角色标注是这条线的骨架，升级方向是把访客能力授予纳入账本授权。

## 实施顺序

1. digital-twin 预设全工具化（决策四，前置）
2. dsh-task-board 数据层：任务模型 + Host 权威账本 + 原子写
3. 执行器：会话创建/钉扎/fail-closed + 账本裁决闭环
4. cron 调度 + 确定性恢复
5. 看板 UI + 今日待办联动
6. 续接卡 + 交接包 + 可选项（idle-sleep/公告注入）
7. 测试收尾 + 套件集成（第 10 个子模块）+ install-all.bat 安装段
