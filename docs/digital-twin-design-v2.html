数字分身 · V2 阶段设计

「越用越像」：把主人的每一次纠正与每一次交往，安全地变成分身的能力
版本 v0.1 · 设计稿 日期 2026-09-02 上游：设计文档 v0.2 §4.4/§4.6 · 实施方案 v1（已交付） 范围：学习闭环 · 样例引擎 · 关系档案 · 影子测试底座

1阶段定位

v1 回答了"敢不敢用它"；v2 回答"它会不会越来越对"。

v1「可托付」交付了权限、身份、审计与人格的四张卡表达。v2 打开成长通路：让分身从主人的纠正、真实交往与历史语料中变得保真，同时严守 v0.2 设计确立的纪律——只做确认式学习，永不做隐式漂移。

v1 已经为 v2 预埋了全部地基，本阶段是把这些接缝上的应用层建起来：

v1 已交付的地基v2 在其上建什么
账本 outcome.masterFeedback（认可/推翻）否决信号 → 策略卡修订建议的学习路由
记忆 support 支持度轨道 + relation 关系轨（观察/推断/开环）关系档案视图 + 装配自动回注 + 推断转正流
四张卡 exemplars（source: 语料|纠正, confirmedAt）+ 修订快照样例引擎：挖掘 → 候选池 → 确认入卡
dsh-regression 场景集 + 评估纯函数 + HostRunner 接口影子测试协议 + HostRunner 会话 API 落地

阶段目标（设计 v2 验收口径的定性表述）：纠正 → 入卡全链路版本化可回溯；同一客户第三次来访，分身记得前两次；影子盲测的分辨不出率持续上升且有度量。

2总览：三条主线一个底座

图 1 · V2 总览：三类信号经学习闭环路由到四张卡；关系档案让历史"被看见"；影子底座提供真实模型度量

3主线一：学习闭环

把散落的信号变成有门槛、有路由、有签名的修订流水线。

3.1 信号分类与路由

信号来源（全部已有）默认路由目标门槛
纠正会话内主人反馈；IM 文本纠正样例卡候选（对照例）为主单次归档；累计或显式归因入卡
否决账本 outcome.masterFeedback=推翻策略卡修订建议 + 授权边界复核同类否决计数；伴生记忆更正
事实更正主人更正记忆内容事实轨替代链（v1 已有）+ 支持度调整主人显式确认即生效
影子差异影子测试与主人实际回复的分歧样例卡候选（低权重观察）仅产出报告，不自动入卡

3.2 证据权重门槛（机制化"合度"）

LearningEvent {
  id, ts, kind: 纠正|否决|事实更正|影子差异,
  sig: { 指纹: 归一化后的信号要点, target: 样例卡|策略卡|记忆, ref? },
  weight: 1|N,  by: "主人",  status: 观察|候选修订|已入卡|已驳回
}
晋升规则：同类指纹累计 ≥ N（默认 N=3）或 主人显式归因（一次即候选）
         → 生成候选修订 → 主人确认 → 回归 → 入卡

指纹 = 纠正要点的归一化文本（NFC、去标点、截断），同类判定即指纹相等；N 可按信号类别配置（默认 3）。所有事件只增不删，驳回也是记录。

3.3 变更流水线

  1. 信号捕获纠正经主人反馈通道（IM 按钮/命令/设置页）；否决复用账本 feedback；均落 LearningEvent。
  2. 候选生成按路由表产出候选：样例卡对照例（situation/say/avoidSay）或策略卡规则修订建议——只生成，不生效。
  3. 主人确认设置页「学习队列」逐条确认/驳回；确认即签名。
  4. 回归门禁入卡前自动跑 v1 场景集；报告随修订快照存档——检查通过不等于授权，但不通过一定不生效。

4主线二：样例引擎

行为保真的主引擎：对照式样例的挖掘、脱敏与确认。

4.1 两个来源

纠正转化（自动候选）

学习闭环产出的纠正，天然携带 situation（触发场景）与 avoidSay（被否决的说法）；say 由主人的修正话术或分身的下一版回答填充。来源标记「纠正」，携带事件引用。

语料挖掘（授权批量）

从主人真实历史对话按显式授权范围挖掘高价值场景（拒绝话术、边界表态、承诺措辞）。产出入候选池，默认按「候选」对待——来源登记不等于入卡。

4.2 挖掘管线（语料来源适用）

  1. 授权接入沿用 inbox 语义：主人指定可挖掘的会话/时间范围，范围外一律拒绝读取；范围授权一次性、可撤销。
  2. 候选抽取识别四类高价值模式：拒绝/边界表态、承诺措辞、语气显著个人化的回复、纠正式改口。每条候选带出处引用。
  3. 脱敏候选写入候选池前过脱敏规则（与 dsh-redact 同源的密钥/证件/账号类目）：样例会进入提示词，真实敏感值不得进入样例，一律替换为占位描述。
  4. 确认入卡候选池 → 主人逐条确认 → 样例卡（confirmedAt 签名）→ 自动触发回归 → 生效。
为什么候选池与卡分离
样例卡会直接塑造分身行为并进入提示词前缀——它是"人格"而非"素材"。挖掘的量级（可能数百条）与质量（未经验证）都不允许直通入卡；候选池是噪声的隔离区，确认是质量的闸门。

5主线三：关系档案

"同一个客户第三次来访，它记得前两次"——靠的不是会话记忆，而是关系轨的自动回注。

5.1 装配自动回注（关键机制）

v1 已有关系轨数据，但数据不被装配就不是记忆。v2 在 assemble 中新增关系摘要段：当对话者已注册（actorId 命中）时，自动附上该对话者的档案摘要——

【关系档案 · 客户A】
- 待跟进：报价方案已转主人（2 天前，未闭环）
- 已承诺：下周内给答复（3 天前）
- 观察：曾询问 A 产品报价与交付周期（1 周前）
  • 顺序：未闭环开环（按时间倒序，最多 5 条）→ 近期观察/推断（最多 5 条，标注「推断」）；
  • 预算：关系摘要段有字节上限（默认 1200 字节），超限按开环优先裁剪；
  • 可见性：复用 v1 规则——该摘要只对主人与当事人本人装配，他人结构性缺失。

5.2 推断转正流

「观察」（实际发生的对话）可由主人升格为「推断」（对意图/偏好的判断），推断经确认可成为策略输入；每次升格都是带签名的转正记录。降权（推断证伪）同样走确认，并回写支持度轨道。

5.3 关系档案页

设置页新增「关系档案」视图（按对话者）：角色与绑定渠道、观察/推断时间线、开环清单（可标记闭环）、支持度标注、该对话者相关的账本记录跳转。数据全部来自 v1 已有的 relation 轨 + 注册表 + 账本，本阶段只建聚合视图。

6底座：影子测试与 HostRunner

"像不像"必须有度量。影子测试是 v2 的度量基础设施，其前置是 v1 的遗留项 HostRunner。

6.1 HostRunner 会话 API（升格为 v2 首个任务）

补齐 v1 遗留：dsh-regression 的 HostRunner 通过 dsh 会话接口驱动临时会话跑场景（数字分身预设 + 指定 actor 视角），结束后会话即弃。约束：临时会话标记为 dryRun=true（不进生产统计、不触发真实外发——账本对 dryRun 会话的 L2 动作一律走"模拟批准"路径并显式标注）；并发上限 1；单场景超时 120 秒。

6.2 影子测试协议

  1. 样本对生成从授权语料中选取「主人真实回复」的历史场景，隐去主人原文，让分身对同一访客输入生成回复，形成盲测对。
  2. 主人盲测设置页逐对呈现（随机左右），主人选择哪句是自己写的；可跳过。
  3. 度量与产出分辨不出率 = 主人选错/弃权的比例（滚动窗口）；分歧对自动生成样例卡候选（低权重观察，走确认）。

隐私边界：盲测对仅在本地生成与展示；度量只落指标（比例、样本数、时间），不落对话原文；原文留在授权语料范围内，随授权撤销可清理。

10边界与不做的事

  • 不做隐式学习一切人格变更必须主人签名；影子差异只产候选观察。
  • 不自动挖语料挖掘必须有显式授权范围；授权一次性、可撤销、范围外拒绝。
  • 样例不携带真实敏感值脱敏在入池前完成；占位描述替代真实值。
  • 影子测试不触碰真实外发dryRun 会话的 L2 动作一律模拟批准并显式标注。
  • 不做关系记忆的向量检索回注按时间与开环优先级确定性选取；检索升级仍属 v3 评估项。
  • 状态卡汇入与主动性仍属 v3，本阶段不引入任何主动触达。
